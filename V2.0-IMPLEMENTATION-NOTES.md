# Huddl V2.0 implementation notes

## Changes in this copy

- Private events remain discoverable as date/time cards. Authenticated clients cannot select `events.location_name`, `events.description`, or private event host IDs through the table API. Member-aware RPCs return private location and description only to the host or a current member. The interface also hides the location, host identity, attendee count panel, and attendee names until membership.
- Onboarding and profile edits share the same profile-sports save operation. It upserts selected sports first and removes only obsolete associations, so a failed save does not erase every existing sport preference.
- Friend requests and friendship changes now run through authorization-checked database functions. Authenticated clients no longer have direct table write access that can change request participants/status or create/delete friendship rows independently.
- Event messages are append-only to authenticated clients; a sender cannot move or rewrite a message after sending it.
- Sport/esports event edits use a single transactional RPC, validate ownership and inputs, prevent capacity from dropping below current attendance, and recalculate `upcoming`/`full` status when capacity changes.
- Event detail metadata and the attendee panel are separate Svelte components. Existing card, navigation, and auth UI components remain in use. See [ARCHITECTURE.md](ARCHITECTURE.md) for the SvelteKit file layout and conventions.
- Handles are checked against the app's `@name` format before saving.

## Database rollout

The new forward migration is `supabase/migrations/20261018090000_private_event_preview_and_access.sql`. It has not been applied to any database. The archived migration history is incomplete, and the existing `20261009041000_final_access_guardrails.sql` is also a prerequisite candidate that has not been verified against staging. Reconcile the live schema and migration history, apply prerequisites in a staging project, then validate private-event access and all event, friend, message, and rating flows before production rollout. Do not deploy this client against a database missing its new RPCs.
